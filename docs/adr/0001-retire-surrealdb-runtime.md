# ADR 0001: SurrealDB 通常運用の廃止と SQLite への一本化、およびネイティブ fetch による移行ツールの独立化

## ステータス

Accepted

## 日付

2026-09-17

## コンテキスト

Radiora v2 では初期フェーズにおいてグラフ・ドキュメント指向データベースとして SurrealDB
を採用し、通常運用を行っていた。しかし、デスクトップ環境における起動オーバーヘッド、プロセス管理の複雑性、配布バイナリサイズ等の課題から、v0.5.0
より SQLite（`sqlite_store.ts`）への全面移行が実施された。

SQLite への移行後も、旧バージョン（v0.4 以前）の SurrealDB
データベースを保有するユーザーのための移行スクリプト（`scripts/migrate_legacy_surreal.ts`）を提供し続ける必要があった。しかし、以下の構造的課題が存在していた：

1. **通常運用資産との密結合**: 移行ツール（`legacy_surreal_exporter.ts`）が通常運用時の
   `SurrealGraphStore` や各種 Repository（Work, Outline, Relation, Revision, Discovery 等、計 25
   ファイル超）を動的インポートしており、旧来の SurrealDB 関連コードを削除できなかった。
2. **ランタイム互換性の制約**: Deno Desktop 環境下において、公式の `npm:surrealdb`
   パッケージ（WebSocket / Node.js
   ポリフィル依存）が正常に動作せず、ランタイム不整合を引き起こす問題が判明した。
3. **品質維持コスト**:
   通常運用を行わないコードに対しても、品質ラチェット（実装行数、重複コード、マジックナンバー）や型検査の保守コストが発生し続けていた。

## 決定事項

1. **SurrealDB 通常運用資産の完全削除**:
   - 通常運用用の Store、Repository
     群、専用マイグレーション（0001〜0007）、行マッパー、スキーマ定義、および通常運用用テストをコードベースから削除する。
2. **移行ツールの完全独立化（Plan A: ネイティブ fetch API 方式）**:
   - `npm:surrealdb` パッケージを `package.json` から完全に削除（ゼロ依存化）する。
   - 移行専用モジュール `src/storage/legacy_surreal_migration_reader.ts`
     を新設し、一時起動したローカル SurrealDB の HTTP REST
     API（`http://127.0.0.1:${port}/sql`）に対して標準の `fetch()` で SQL クエリを一括送信し、16
     テーブルのデータを JSON として取得・マッピングする方式を採用する。
   - 旧プロセスの起動・停止管理（`src/desktop/surreal_process.ts`）のみを移行専用ツールとして残し、通常運用コードからの呼び出しを排除する。
3. **単一アーキテクチャの確立**:
   - Radiora v2 のストレージバックエンドは SQLite を唯一の標準とし、テスト・開発用のインメモリ／JSON
     ストレージを副次的に維持する。

## 結果と影響

- **正の影響**:
  - 約 5,800 行に及ぶ旧 SurrealDB
    関連の不要ファイルが削除され、コードベースの明瞭性と保守性が大幅に向上した。
  - 外部 npm パッケージ（`surrealdb`）の排除により、依存関係ツリーがスリム化され、Deno Desktop
    環境でも 100% 確実に動作する堅牢な移行経路が確立された。
  - 品質ラチェット（jscpd 重複、Biome
    マジックナンバー）から旧コードの除外設定が整理され、コードベースの健全性が向上した。
- **負の影響・トレードオフ**:
  - 移行元としてサポートされる SurrealDB のデータ形式は v0.4
    最終時点のスキーマに固定され、それ以降の SurrealQL
    変更には追従しない（通常運用の廃止に伴い不要と判断）。
