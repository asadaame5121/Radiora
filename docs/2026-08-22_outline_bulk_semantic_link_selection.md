# アウトライン上の意味関係一括選択UI計画

## 1. 目標

選択中の項目を起点として、アウトラインの階層や周辺項目を見ながら複数の対象を選び、同じ種類・向き・説明の意味関係を一括設定できるようにします。

検索結果だけを表示するインスペクター内ではなく、普段文脈を把握しているアウトライン上で対象を選べることを重視します。

## 2. 操作フロー

1. 起点となる項目を通常どおり選択する。
2. 「意味関係を追加」を実行する。
3. アウトラインが一時的な「意味関係を追加中」モードになり、各対象行にチェックボックスが現れる。
4. 同じ関係を設定したい項目を複数選択する。
5. 固定表示される操作バーで、関係の種類、向き、説明を指定する。
6. 「X件を接続」を押して一括作成する。

```text
意味関係を追加中
[種類: RELATED ▼] [向き: 起点 → 選択項目 ▼] [説明（任意）]
3件選択                              [キャンセル] [3件を接続]
```

通常時にはチェックボックスを表示しません。アウトラインの編集、行選択、Zoom、ドラッグ操作を増えたUIで常時圧迫しないためです。

## 3. 選択と接続の仕様

### 3.1 WorkとOccurrence

- チェックボックスはアウトラインの行（Occurrence）に表示しますが、意味関係の接続先はその行が参照するWorkです。
- 同じWorkが複数箇所に配置されている場合、どのOccurrenceを操作しても同じWorkの選択状態を切り替えます。
- 同じWorkを参照するすべての表示中Occurrenceでチェック状態を同期します。
- 保存時にも対象Work IDを重複排除し、同じ関係を複数作成しません。
- 起点と同じWorkを参照する行は選択できません。

### 3.2 一括設定

- 選択した全対象へ、同じ関係の種類、向き、説明を適用します。
- 向きは「起点 → 選択項目」と「選択項目 → 起点」から選びます。
- 対称関係では向きの選択を無効化し、既存の正規化規則に従います。
- 対象が0件の間は確定ボタンを無効化します。
- 送信中の二重操作を防ぎます。
- 途中で失敗した場合は選択モードを維持し、失敗内容を操作バーに表示します。作成済みの関係を自動で巻き戻すための新しいトランザクション機構は追加しません。

### 3.3 選択状態の終了条件

次の場合は選択状態を破棄して通常モードへ戻します。

- 一括接続がすべて完了したとき。
- ユーザーがキャンセルしたとき。
- 起点となる項目を変更したとき。
- Zoom先または表示ビューを変更したとき。
- アウトラインのフィルター条件を変更したとき。

折りたたみやスクロールだけでは選択を破棄しません。

## 4. UI構成

### 4.1 アウトライン行

意味関係選択モード中だけ、`OutlineRowItem` の先頭に対象選択用チェックボックスを表示します。

- 行本文をクリックして編集する既存操作は維持します。
- チェックボックスまたはそのラベルだけが対象選択を切り替えます。
- 起点行は「起点」と表示し、チェックボックスを無効化します。
- 同じ起点Workを参照する別Occurrenceも無効化します。

### 4.2 操作バー

アウトライン領域内の見失いにくい位置へ固定表示し、次を持たせます。

- 起点の表示名。
- 関係の種類。
- 関係の向き。
- 説明（任意）。
- 選択中のWork数。
- キャンセル。
- 一括接続。
- 送信エラー。

## 5. 状態所有と変更対象

選択モードの状態はアウトライン行へ分散させず、専用Controllerが所有します。`.svelte`
コンポーネントは表示とイベント通知に限定します。

### [NEW] `src/ui/outline_link_selection_controller.svelte.ts`

次の状態と操作を所有します。

- 起点Work IDと表示名。
- 選択中の対象Work IDのSet。
- 関係の種類、向き、説明。
- 送信状態とエラー。
- 開始、対象切り替え、キャンセル、一括接続。

一括接続は既存の `CreateLinkInput`
とリンク作成APIを対象数だけ呼び出します。専用の一括APIは追加しません。

### [NEW] `src/ui/OutlineLinkSelectionBar.svelte`

Controllerの状態を表示し、種類・向き・説明・確定・キャンセルの入力を通知するViewとします。

### [MODIFY] `src/ui/OutlineView.svelte`

選択モードと操作バーを配置し、各行へ必要な選択状態とイベントだけを渡します。

### [MODIFY] `src/ui/OutlineRowItem.svelte`

選択モード中のチェックボックスと起点表示を追加します。意味関係の状態遷移やAPI呼び出しは置きません。

### [MODIFY] `src/ui/outline_row_types.ts`

選択モード表示と対象切り替えに必要な最小限の型を追加します。

### [MODIFY] `src/ui/App.svelte`

Controllerと既存のリンク作成処理を配線し、ビュー・Zoom・フィルター・起点変更時のキャンセルを通知します。選択ロジック自体は置きません。

### 既存LinkEditor

`LinkEditor`
の検索候補を複数選択化しません。単一の遠隔対象を検索して接続する既存導線として維持します。アウトライン外の複数対象を一括検索する必要が確認された時点で、別途検討します。

## 6. 検証計画

### 6.1 自動テスト

Controllerへ次の最小限のテストを置きます。

- 同じWorkの複数Occurrenceが1つの選択として扱われる。
- 起点Workを選択できない。
- 選択した全Workに同じ種類・向き・説明の入力が生成される。
- 対称関係では向きに依存しない。
- 完了時とキャンセル時に状態がクリアされる。
- 作成失敗時に選択が維持され、エラーが表示可能になる。

```bash
deno task test
```

既存のUI契約テストも更新し、通常モードでアウトライン編集やドラッグ操作が維持されることを確認します。

### 6.2 手動検証

1. 起点項目を選び、「意味関係を追加」を実行する。
2. 選択モード中だけ各行にチェックボックスが現れることを確認する。
3. 複数の対象を選び、件数表示がWork単位で更新されることを確認する。
4. 同じWorkの別Occurrenceでもチェック状態が同期することを確認する。
5. 種類・向き・説明を設定して一括接続する。
6. すべての対象に同じ設定の関係が1件ずつ作成され、通常モードへ戻ることを確認する。
7. キャンセル、起点変更、Zoom、ビュー変更、フィルター変更で選択が破棄されることを確認する。
