# Radiora v2 PoC 検証レポート

- レポート作成日: 2026-07-16
- 主な検証実施日: 2026-07-13
- 対象: Deno Desktop / Svelte 5 による Radiora v2 Technology PoC
- 総合判定: **条件付き合格（自己評価 82/100）**

## 結論

最低限のデスクトップPoCとしては成立している。

Windows実機でアプリが起動しただけでなく、アウトラインの作成・編集・検索・移動・削除・
リンク作成までバックエンドAPIが正常応答した記録を確認した。ドメインテスト、Denoの型検査、
Svelteの静的検査も合格しているため、「偶然ウィンドウが開いた」だけの状態ではない。

一方、自動テストの範囲、JSON保存の耐障害性、ローカルHTTPサーバーの設定には不足がある。
したがって、技術PoCとしては合格だが、日常利用版や正式実装としての合格ではない。

## 実施した検証

### Windows環境

以下の結果を確認した。

```text
npm run check
  svelte-check found 0 errors and 0 warnings

deno task test
  5 passed / 0 failed

deno check src/main.ts
  success
```

`%LOCALAPPDATA%\RadioraV2\logs\startup.log` では、2026-07-13に以下のAPIが
ステータス200で完了していた。

- `updateItemText`
- `createItem`
- `listOutline`
- `searchItems`
- `moveItem`
- `deleteItem`
- `createLink`

### WSL環境

`deno task test` と `deno check src/main.ts` は成功した。

`npm run check` と `npm run build` は、Windows用に導入された `node_modules` をWSLから
使用したため、Linux版Rollupのネイティブモジュール不足で実行できなかった。これは既知の
環境混在問題であり、READMEにもWindowsとWSLで `node_modules` を共有しないよう記載されている。
実装上の失敗とは判定しないが、再現性上の弱点として扱う。

## 合格と判断できる理由

1. UI、RPC、サービス、永続ストアまでの縦方向の経路が接続されている。
2. 主要操作がWindows実機上で成功している。
3. 階層操作、子昇格、循環検出、検索、JSON再読込の中核ロジックに自動テストがある。
4. Windows環境のSvelte静的検査とDeno型検査が合格している。
5. LadybugDBとSurrealDBの不具合に固執せず、事前の撤退条件に従ってJSONへ切り替えている。

## 残存問題とリスク

### 1. 自動テスト範囲が狭い

テストは5件のみで、次の経路は自動検証されていない。

- リンクの作成・削除・重複処理
- 折りたたみ状態の保存と復元
- 起動中、起動失敗、再試行のRPC
- UI上のキーボード操作とドラッグ操作
- デスクトップbundleを使ったE2E
- 破損または不正なJSONデータの読込

### 2. JSON保存が原子的ではない

現在は保存先ファイルへ直接書き込むため、書込み中のプロセス終了やディスク障害によって
JSONが途中までの内容になる可能性がある。正式利用へ進める場合は、一時ファイルへの書込み、
flush、renameによる置換、バックアップ保持を検討する。

### 3. 複数操作がトランザクション化されていない

親変更とアイテム更新などが別々の保存になる。途中で失敗すると、一時的または永続的に
整合しない状態が残る可能性がある。

### 4. HTTPサーバー設定の明示がない

`Deno.serve()` にhostとportの明示指定がない。固定ポートとの衝突、待受範囲、ローカルAPIへの
アクセス条件を実機で確認し、必要ならループバック限定および動的ポート化を行うべきである。

### 5. グラフDB構成は未達

当初候補のLadybugDBとSurrealDBは実機上の問題によってdesktop版から外れ、現在の永続化は
JSONである。PoCの撤退判断としては妥当だが、グラフDBを採用した完成構成の実証にはなっていない。

### 6. 最新ソースからのbundle再生成は今回未実施

既存のWindows bundleと実機稼働ログは確認したが、このレビューでは状態を変更しない方針とし、
最新ソースから `deno task desktop` を再実行してbundleを作り直す検証までは行っていない。

## 次の合格基準

正式開発へ進む前の最低ラインとして、次を推奨する。

1. リンク、折りたたみ、起動失敗を含むサービス／RPCテストを追加する。
2. JSON保存を原子的な置換方式にする。
3. ローカルHTTPサーバーの待受範囲とポート戦略を確定する。
4. Windowsのクリーン環境で依存導入、検査、ビルド、起動、主要操作の一連のスモークテストを行う。
5. 正式版でJSONを継続するか、別の永続化方式を再検討するか決定する。

## 最終自己評価

**PoCとしては合格。製品品質としては未合格。**

今回の成果は、Deno DesktopとSvelteによるローカルデスクトップアプリの最小構成、および
Radioraの中心的なアウトライン操作が成立することを示した。ただし、稼働確認をそのまま
完成判定にはせず、上記の耐障害性と検証範囲を次段階の課題として引き継ぐ。
