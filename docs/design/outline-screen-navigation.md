# Outline に戻るための画面遷移設計

2026-10-03。Issue #239 / PR #285 の設計を、利用者から示された機能の範囲に合わせる。
この文書は、共通ナビゲーションと保持した Outline への復帰の実装契約を定める。
全画面選択とpane選択、live stateと復帰文脈、snapshot/draftの所有とwriterは
[UI所有契約](ui-state-ownership.md)を参照する。

## 機能の範囲

「戻る」は、Outline を離れて開いた画面から、保持していた Outline へ戻る操作とする。 たとえば Outline
→ Tree → Help と移動した場合も、戻り先は Outline。 Outline
の項目選択、Hoist、フィルター変更、Inspector のタブ切替は、戻る履歴に追加しない。 Outline
上では画面の「戻る」を無効にする。

文章、配置、折りたたみなどの保存済みデータは、戻る操作によって過去の内容へ巻き戻さない。 Undo/Redo
は操作履歴を扱う別機能として、今回の実装範囲から外す。
既存の「元の編集位置へ戻る」も特定位置への移動であり、Undo/Redo ではない。
その移動も、以下の共通窓口を通す。

## Outline の状態を保持する

Outline の状態は Outline の feature が所有する。別画面で選択した Work や項目で、 保持中の Outline
の選択・Hoist を上書きしない。 画面遷移の Controller がすべての feature
の状態を所有する構造にはしない。

| 保持する状態                     | 復帰時の扱い                                                                                |
| -------------------------------- | ------------------------------------------------------------------------------------------- |
| ペインとアクティブペイン         | 同じペイン構成・アクティブペインへ戻る                                                      |
| 各ペインの選択と Hoist           | 同じ配置と範囲へ戻る。Work ID だけでは配置を識別できないため occurrence ID を使う           |
| フィルター、表示のための一時展開 | 離れた時点の表示条件へ戻る                                                                  |
| Inspector の表示・タブ           | Outline を離れた時点の表示へ戻る                                                            |
| Outline の表示モード             | 通常編集・原稿表示のどちらだったかを保持する。原稿の本文・保存状態は原稿 feature が所有する |
| 編集対象とキャレット・選択範囲   | 最後尾の行・空の行を含め、同じ対象と位置へ戻る                                              |
| エディターとペインのスクロール   | フォーカス処理の後に保存位置を復元する                                                      |
| フォーカス先                     | エディター、行、空の Outline など、選択とは別に識別する                                     |

キャレットは開始位置・終了位置・選択方向を持つ。選択中の項目からフォーカス先を推測しない。
テキストが短くなっている場合は、最新の長さに収まるよう位置を補正する。 現在の DOM
ノードは保存せず、再描画後に識別子から対応する UI を取得する。

保存済みの本文や折りたたみ状態は、最新のデータを表示する。
削除された選択対象は選択なしに、削除された Hoist は全体表示に補正する。
残っている表示条件・スクロール・有効な選択は保持し、復帰だけを理由に項目を作成しない。
復帰先データを取得できない場合は元の画面に留まり、保持状態を消さず再試行できるようにする。

Outline の DOM を常時マウントして隠すことは、状態保持の前提にしない。 論理状態は Controller
に残し、DOM にしかないキャレット・スクロールだけを UI adapter で捕捉する。 ツールバーのクリックで
blur した場合も失わないよう、編集位置は編集側のイベントで追跡する。

## 共通のナビゲーション窓口

画面の変更を確定できる窓口を `ScreenNavigationWorkspace.navigate(destination)` に一本化する。 View
や feature は遷移先の値を渡す。選択・Hoist を先に変更してから画面を開く処理や、
呼び出し側に確定コールバックを返す `prepareOpen()` は最終的な公開 API に残さない。

実装の公開 API は `ScreenNavigator`。すべての呼び出し側は次のように値だけを渡す。

```ts
// 単に Outline へ復帰する。保持していた状態を使う。
await navigation.navigate({ view: "outline" });

// 検索結果など、移動先を明示する操作。
await navigation.navigate({
	view: "outline",
	occurrenceId,
});

// 比較対象の取得・適用も共通窓口が feature port を介して調整する。
await navigation.navigate({ view: "comparison", comparison: { kind: "link", linkId } });
```

「戻る」、Help の Outline ボタン、Outline へ切り替えるショートカットは `{ view: "outline" }`
を渡す。 検索結果、Recent、Today の配置、内部参照などは `occurrenceId` を明示する。
明示的な項目への移動は、その項目を表示できる範囲に移動する。 保持中の Hoist 内なら Hoist
を維持し、範囲外なら解除する。Zoom は対象の Hoist を明示する。 受理された項目移動以降は、その
Outline の状態が次の復帰先になる。

Outline 内の通常の選択・Hoist は Outline feature の責務として残す。 他画面から Outline
の選択を変更する操作は、必ず遷移先として共通窓口へ渡す。 Inspector
のタブ切替だけでは画面遷移を起こさない。

## 遷移の処理順序と不変条件

1. 要求を受け付けた時点で要求番号を進め、移動元を固定する。 Outline
   を離れる場合は、この時点の状態を復帰候補として捕捉する。
2. feature のガードを通し、必要な保存を待つ。
   ガードは受理・取消を返すだけにし、移動先の選択やフォームへの切替を確定しない。
3. 移動先のデータを取得し、最新のデータに対して表示状態を検証・補正する。
   取得結果は準備中の値とし、表示中の選択・比較・Outline の状態には適用しない。
4. 最新の要求であることを確認し、同期処理で feature 状態と画面を一緒に確定する。 確定処理には
   `await`・I/O・追加のガードを含めない。保持する Outline 状態もここで確定する。
5. 描画後にフォーカス・キャレット・スクロールを復元する。
   この処理も要求番号を確認し、別の遷移が始まっていたら適用しない。

Cancel、保存失敗、取得失敗では画面・移動先の選択・保持中の Outline 状態を変更しない。
ユーザーが明示的に選んだ保存・破棄の結果は、それぞれの feature の処理として扱う。
画面遷移に失敗したからといって、成功済みの保存を巻き戻さない。

新しい要求は、確定の有無にかかわらず古い要求を無効にする。 比較取得中に Help
を開いた後、古い応答が画面・選択・比較状態を変更してはいけない。
ガードの古い承認コールバックも、移動先のフォームを含め、状態を変更してはいけない。
確認ダイアログは同時に複数を開かず、無効になった要求の待機を解消する。

作成・配置などの DB 変更は Work / BranchRewrite feature が所有する。
その操作の開始時点の要求・移動元を識別し、完了後の移動先を共通窓口へ渡す。
操作中に別の遷移要求が始まった場合、遅れて完了した操作から自動で画面を移さない。
作成済みデータは残す。ナビゲーションの取消と DB 操作の取消を同一視しない。

原稿の保存・再読込も、保存のために項目を再選択する契約をやめる。 feature
は保存結果を返し、移動先への選択と表示モードの確定は共通窓口が扱う。
表示モードに反応してフィルターを消す `$effect` は廃止し、必要な初期化を遷移先の準備に含める。

## History API と UI

現行実装はブラウザの `pushState` / `replaceState` / `popstate` を使っていない。
旧実装の汎用画面履歴スタックは削除した。保持するのは Outline
の復帰状態であり、ブラウザ履歴・操作履歴・ペイン内の移動履歴とは別にする。 History API
は今回導入しない。

戻るボタンは、画面を切り替えても位置が変わらない共通トップバー左側に置く。
表示・アクセシブル名を「アウトラインに戻る」に揃え、Outline 上では無効にする。 画面内の既存の
Outline 復帰ボタンも同じ `{ view: "outline" }` を使う。 Alt+← は同じコマンドへ委譲する。IME
変換中・モーダル操作中は実行しない。 将来ブラウザ Back/Forward や URL を導入する場合も、adapter
から同じ窓口へ要求を渡す。

## テストから始めた移行

最初に共通窓口の契約テストを作り、旧実装で失敗することを確認してから置き換えた。
旧来の画面履歴スタックを期待するテストは、現行仕様を検証するテストに更新した。

| ケース                                           | 確認する結果                                                 |
| ------------------------------------------------ | ------------------------------------------------------------ |
| Hoist 中の Outline → Tree → Help → 戻る          | 元の Outline の Hoist・選択へ一度で戻る                      |
| 最後尾の行で本文末尾にキャレット → 別画面 → 戻る | 同じ行の末尾にキャレットが戻り、スクロールも戻る             |
| 空行・選択なし・複数ペインからの復帰             | 保存したフォーカス先とアクティブペインが戻る                 |
| 別画面で別 Work を選択 → 戻る                    | Outline を離れた時点の選択を保持する                         |
| 原稿表示からの復帰                               | 表示モードを保持し、保存済みの最新本文を使う                 |
| Outline 内の選択・Hoist・Query タブの変更        | 画面の戻るが有効にならない                                   |
| 明示的な項目移動、Hoist 内・外への移動           | 対象へ移動し、定めた Hoist の扱いになる                      |
| ガードで Save / Discard / Cancel、保存失敗       | 受理された場合だけ画面と移動先を確定する                     |
| 比較取得・ガード待機中に別の要求                 | 古い処理は選択・フォーム・比較・画面・フォーカスを変更しない |
| 作成・配置の完了前に別画面を開く                 | DB 操作の結果を残し、完了後の自動遷移を抑止する              |
| 復帰対象の削除・本文短縮・取得失敗               | 補正または画面維持を行い、保存済みデータを巻き戻さない       |

ガードの判定と移動先への適用を分離し、共通窓口と Outline 復帰状態を実装した。 UI
のキャレット・スクロール・選択方向・空の Outline のフォーカスをブラウザテストで確認する。
以下の経路を移行し、呼び出し側の `openView` / `prepareView` / `reload(..., afterSelection)`
による画面遷移契約を削除した。

- `App.svelte`: Recent、検索・内部参照、各配置、疎アウトライン、コンテキストメニュー、 タグ、Help /
  Option、Inspector からの画面移動。
- `WorkController` / `BranchRewriteController`: 一覧を開く処理、作成・配置後の自動移動。
- `ComparisonController` / `DateProjectionController`: 比較・日付投影の取得後の移動。
- `KeyboardWorkspaceController` / `EditorReturnController` / `LongFormController`:
  ショートカット、編集位置への復帰、原稿の保存と表示切替。
- `ScreenNavigationWorkspace`: Query の同一画面履歴と、汎用の画面履歴スタックを除去。

完了条件は、各経路の順序を個別に注意して守ることではなく、
呼び出し側が画面・移動先の選択・復帰状態を個別に確定できない API になっていることとする。

## 実装の責務

- `ScreenNavigationController`:
  要求番号・画面の公開・非同期操作の移動元を識別する受領番号を所有する。
  受領番号は要求開始と受理時の両方で更新し、処理途中から始まった DB 操作の自動移動も無効にする。
- `ScreenNavigationWorkspace`: 保存、選択ガード、取得、同期確定、描画後の復元を調整する。
  明示的な配置が未取得の場合は、ガード対象を解決するため Outline を先に読む。 Save
  を選んだガードの後に必ず最新の Outline を取得し直し、保存前のデータを公開しない。
- `OutlineScreenState`: 休止中の Outline 文脈を所有する。本文のスナップショットは保持しない。
- `OutlineViewportAdapter`: DOM のフォーカス・キャレット・スクロールの捕捉と復元を所有する。
  フォーカス追跡のリスナーはマウント時に登録し、破棄時に解除する。
  明示的な項目移動では対象が見える位置へスクロールし、保持した文脈への復帰では元の座標を復元する。
- `ScreenDestinationPresenter`: 比較、日付投影、Work 一覧、タグ管理の feature port を組み合わせる。
  feature の取得結果を公開する同期 port はこの内部境界に限定し、遷移を要求する側には返さない。

Outline 内の編集操作に残る選択コールバックは、その feature 内の選択・Hoist のためのもの。 画面切替や
Outline の復帰先を確定するコールバックとしては使わない。

## 日付範囲を変更する要求

`pendingView` は共通窓口が所有し、要求開始からガード・取得・同期確定・描画後の処理までを覆う。
終了時には要求番号を確認し、古い要求の完了で新しい要求の取得中表示を解除しない。 Today
はこの状態を使って取得中の旧結果を隠し、範囲の入力と操作を一時的に無効にする。
別画面への移動は引き続き新しい要求として受け付ける。

前日・翌日・週・今日の範囲は、遷移先の値として窓口へ渡す。
表示中の日付入力と投影結果を変更するのは、feature preparation port の同期公開時だけとする。
失敗・古い応答では、最後に受理した範囲と投影結果を保持する。
手入力途中の日付は入力のドラフトとして保持し、結果には投影自体の期間を表示する。
入力の変更や取得失敗で、既存の結果を新しい期間のものとして表示しない。

Tree のフォーカスは UI adapter が選択ノード、最初のノード、Tree SVG 本体の順に取得する。
空またはフィルターでノードが消えた場合も、Tree 内へキーボードフォーカスを移す。
