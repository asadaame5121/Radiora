# v3 初回提供範囲と完成条件

策定日: 2026-10-30。担当: [#382](https://github.com/asadaame5121/Radiora/issues/382)。 状態:
ユーザーから委任された推奨判断による初回範囲の決定。実装・配布・G2/G3承認ではない。
基本モデルは[v3決定事項](v3-model-decisions.md)、名前/検索は[名前契約](v3-naming-and-search-contract.md)、
工程は[Tauri全体計画](tauri-migration-plan.md)と[移行バックログ](tauri-loro-transition-backlog.md)に従う。
各Fの検証責任・合格条件は[検証対応計画のV01〜V16](v3-verification-plan.md#2-初回範囲の検証対応表)へ対応付ける。

## 1. 「初回」の意味

初回は、Tauri版で文書を作り、アウトラインと縦Treeで編集し、名前で探し、
Relationで結び、バックアップから復元できる日常利用候補とする。
最小の#385保存slice・固定fixtureのPoC・初回機能の完成・配布・G2利用切替は別の到達点である。

- **初回必須**: 欠けた状態では初回提供範囲の完成としない。
- **後続**:
  今回は画面/新規操作を提供しない。保存済み情報の保全・読出し/export/backup復元は別途必須。
- **初回対象外**: 既存決定で今回実装しないもの。将来の恒久廃止や旧情報の破棄許可ではない。

v2の変換規則は本書で確定しない。#384の対象情報保全・変換fixtureが未成立なら、PoCは進められても
実データのG2切替条件を満たさない。未対応のrecordや機能を黙って落として「移行完了」としない。

archive保護は個別機能の再実装を要求しない。
初回にはarchiveの種別/件数/保存形式/未変換理由の一覧と、原recordを読取り専用で確認・取り出す導線を設ける。
元ID・参照・型・日時・payload・必要な関連assetを保持し、native
backup→空DB復元→再exportで情報を照合する。
通常検索でarchiveまで黙って混ぜず、「現在の文書」と「旧保留情報」を区別して閲覧する。
archiveの具体形式・全record写像・未対応値の扱いは#384の未決を解消してから実装する。

## 4. 維持する初回対象外と承認境界

- root降格・文書統合専用操作、独立原稿編集ビュー、参照項目上での共有本文直接編集。
- pane別独立Undo、独自の選択的Undo、再起動を越える永続Undo。
- 共同編集・端末同期、ATProto等の外部公開/同期。
- Loro履歴/backupまで含む物理抹消、旧DBの破棄・in-place変換・dual-write。
- 現行Deno版への新機能追加。旧runtimeの撤去・利用切替・release/tag/pushは既存の別承認に従う。

irohによる端末共有、atproto PDSへの暗号化native backupは移植が一段落した後の将来案とする。
接続境界と残る同期/鍵管理/保持の仕様は[アーキテクチャ](v3-architecture.md)に記録し、初回必須へ追加しない。

「後続」は開発順を今回から分ける決定であり、旧保存データの削除・Issueのclose/Not
Plannedを意味しない。
初回にない機能の情報保護が未成立ならG2を通さず、旧版・原本・backupの保全と復帰限界を確認する。

| 段階       | 先に証明するもの                                      | 全体範囲との関係                                                           |
| ---------- | ----------------------------------------------------- | -------------------------------------------------------------------------- |
| T-00/01/03 | 採用契約、名前/到達ID、F表の受入fixtureとDTO          | 名前/初回scopeを再び未決へ戻さない。#384の変換詳細は別                     |

| T-07/08    | F02〜F14の個別command/UIと縦Treeへ接合                | 同じwriter/Controller/DTOを再利用し、名前やバックアップを別の正本にしない  |
| T-09       | F01〜F16の採用範囲全体、実機/性能/配布/復旧           | 各Fに固定fixture・結果・既知制約・実装PRを対応付け、未接続を完了扱いしない |
| T-10/11    | G2利用切替、G3退出の別判断                            | 機能表の策定・PoC成功・配布とユーザー承認を区別                            |

名称変更後も名前/別名/固有見出しで同じIDへ到達すること、参照項目へ直接到達できること、
削除済み本文/名前の非露出、Undo後の整合、native backupの別DB往復を横断シナリオへ含める。
製品UI・保存失敗・応答逆順・設定保存失敗・crash・大規模graphを、文字列検査だけで合格にしない。

後続機能を追加しても新しい初回必須の正本や汎用plugin層を作らない。
検索順位や正規化変更は原文から索引再構築、scope変更はF表/受入の更新で扱える。
名前の所有・Relationの同一性・backup互換性を変える場合は、version付きmigrationと互換性fixtureを伴う。
