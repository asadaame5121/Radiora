# v3 名前・別名・検索／補完の契約

策定日: 2026-10-30。担当: [#290](https://github.com/asadaame5121/Radiora/issues/290)。 状態:
ユーザーから委任された細部の推奨判断として採用するv3仕様。実装・旧データ変換・Issue完了を意味しない。
基本モデルは[v3決定事項](v3-model-decisions.md)、初回範囲は[初回提供範囲](v3-first-release-scope.md)を参照する。

## 1. 名前の所有と到達先

root BlockがTopicタイトルを兼ねる。独立したタイトルfieldを追加しない。
通常Blockにも同じ表示名抽出を使い、本文を所有するBlockへ別名を付けられる。
参照項目にはその配置固有の見出しを付けられる。表示本文は代表の読取り専用のままとする。

| 種類                     | 表示名・保存対象                                               | 通常検索                                     | 内部リンク／Relation補完                           | 到達先                                                           |
| ------------------------ | -------------------------------------------------------------- | -------------------------------------------- | -------------------------------------------------- | ---------------------------------------------------------------- |
| Topic root               | root本文の最初の非空行から導出。別名はrootのmetadata           | 表示名・別名・本文                           | 表示名・別名                                       | rootの論理Block ID                                               |
| 通常Block                | 本文の最初の非空行から導出。別名は当該Blockのmetadata          | 表示名・別名・本文                           | 表示名・別名                                       | 当該Blockの論理ID                                                |
| 固有見出しのある参照項目 | 見出しは参照項目のmetadata。代表本文や代表の表示名を変更しない | 固有見出し                                   | 固有見出し                                         | その参照項目の論理ID                                             |
| 固有見出しのない参照項目 | 代表Blockの表示名を描画上のfallbackにする                      | 代表本文／名前の一致は代表側の結果へまとめる | 代表候補を出し、同じ本文の参照項目を重複列挙しない | 検索／補完では代表。既存リンク・ID指定では参照項目自身へ到達可能 |

参照項目には初回は独立した別名fieldを追加しない。固有見出しが、その配置へ名前を付ける入口になる。
代表の別名を、全参照項目の検索名へ自動複製しない。
参照項目を指す既存リンクや型付きRelationは代表へ付け替えない。
本文を共有すること、本文参照項目の作成、検索結果のまとめ方、Relation
endpointの同一性は別の契約である。

## 2. 表示名・重複・入力

- 表示名は最初の非空行のMarkdown表示上の文字列。装飾記号を名前に含めず、リンクはラベル、inline
  codeは内容を使う。
  本文を書換えず、Markdown解釈は既存の表示と同じ規則へ揃える。正規表現だけの独自Markdown剥離は作らない。
- 空本文はUIで「無題」と補助IDを表示する。「無題」を本文・正式な名前として保存したり検索索引へ登録したりしない。
- 別名と固有見出しはプレーンテキスト。trim後の空白だけの値は保存しない。空の見出しは未設定へ戻す。
- 別名・見出し・本文は利用者の文字列を保持し、検索正規化のために保存値を置換しない。
- 同名Topic、同名Block、他Blockと同じ別名を許す。名前を一意keyにしない。
  同一Block内で検索正規化後に同じ別名は重複保存しない。
- UIの入口は「名前と別名」にまとめる。実体Blockは本文由来の表示名を示して別名を編集、
  参照項目は「この参照項目の見出し」を編集する。適用先と検索への効果を説明する。
- 任意の通常Blockへ本文と別の優先タイトルを追加したり、workspace全体の同義語辞書を追加したりしない。
  旧辞書・旧配置見出しの変換規則は本契約で決めず、#384で情報を保護する。

## 3. 通常検索と補完

初回の検索正規化はNFKC、localeに依存しない小文字化、前後空白除去、連続空白の一つへの集約。
かな／カナの同一視、読み仮名、曖昧一致、形態素／意味検索は初回に追加しない。
この規則は派生索引に適用し、文書や別名の原文は保持する。

### 通常検索

- 通常の入力を空白で区切った語のANDとして扱い、各語は表示名・別名・本文・参照項目固有見出しのいずれかの部分一致でよい。
  初回は正規表現・Query言語・同義語のworkspace全体展開を行わない。空入力では全件検索を開始しない。
- 実体Blockの本文全体（コードを含む）を対象とする。参照項目の表示本文は重複索引にせず、代表の本文結果へまとめる。
  参照項目の固有見出しは、その項目へ到達する別の検索対象とする。
- 同じBlockに表示名・別名・本文の複数一致があっても結果は一つ。見出しが一致した参照項目と代表は別IDの結果として区別できる。
- 順序は表示名／固有見出しの完全一致、別名の完全一致、名前系の前方一致、名前系の部分一致、本文だけの一致。
  同順位は論理Block IDの安定順とし、初回は履歴・頻度・選択文脈で順位を変えない。
- 一致した別名／見出し、所属Topic、パンくずを示す。本文一致は該当箇所の抜粋を示す。
  同名は最終的に短いIDでも区別できる。描画上の省略を保存値・索引値へ反映しない。

### 内部リンク・Relation補完

- 本文の `[[` は既定どおり表示名／別名／参照項目の固有見出しの前方一致で候補を出す。
  rootと通常Blockを両方含める。本文の途中に一致するだけのBlockは補完候補にしない。
- Relationのendpoint選択も同じ名前候補と到達IDを使う。参照項目の固有見出しを選べばその項目を指定する。
- 正規化した候補名の完全一致を前方一致より先にし、同じBlockは一候補。
  同名候補を黙って一つへ解決せず、所属Topic・パンくず・参照項目表示・短いIDで選ばせる。
- 候補の表示名とは別に「別名一致」等を示す。挿入ラベルは現在の表示名（参照項目は固有見出し）とし、
  本文由来の表示名が空の場合は一致した別名を使う。正準リンク `[表示名](radiora://block/<UUID>)`
  へ保存し、UUIDを参照の正本にする。
- 本文変更・別名削除・見出し変更で、既存リンクのラベルを一括書換えしない。
  一度作ったリンクは名前が変わっても同じBlockへ解決する。
- 完全なIDを指定した移動・既存リンクの解決は、名前候補の有無と独立に提供する。

## 4. 保存・削除・移動の境界

- 別名と固有見出しは共有する文書metadataでありBackend
  Loroに保存する。SQLiteのローカルfold設定とは分ける。
  変更は一つのcommand／共通Undo一操作。表示名や検索索引は再生成可能な派生値とする。
- 保存成功後、対象の名前・検索・補完・参照表示を失効する。代表の表示名変更では、見出し未設定の参照項目のfallbackも更新する。
  未保存draftは編集UIへ重ねられるが、別の画面の保存済み検索結果として公開しない。
- 移動・文書切り出しではIDと別名／見出しを維持し、所属Topic・パンくずを更新する。
- 複製は別名／固有見出しもコピーし、新しいBlock
  IDのmetadataとして扱う。コピー元と同名でも別結果として識別する。
- 通常削除では名前metadataも復元可能に保持し、通常の検索／補完から除外する。ゴミ箱は別の明示的な読取り入口とする。
- 完全削除では対象集合の本文・別名・固有見出しを除去し、最小ID記録とMissing参照を残す。
  外部の参照項目が所有する固有見出しや本文内リンクラベルまで連鎖削除しない。
- 保存とqueryの版・要求世代・filter/入力範囲を検証し、旧成功・旧失敗・旧finallyで最新候補や画面を上書きしない。
- 選択結果の移動は共通navigationへ渡す。対象までの一時展開は要求元paneだけに適用し、保存済みfoldを変更しない。
  参照項目へ到達しても本文の直接編集はできず、代表へ移動する操作を示す。

## 5. 受入と変更コスト

| fixture                                     | 期待結果                                                    |
| ------------------------------------------- | ----------------------------------------------------------- |
| root「精神分析」、別名「Psychoanalysis」    | 両方で同じrootへ到達し、補完も同じUUIDを保存                |
| 通常Blockに別名、別Topicに同名Block         | 通常Blockを候補に含め、Topic／パンくずで選べる              |
| 参照項目の固有見出し「講義用」              | その見出しで参照項目へ到達。代表の本文と別名は変更しない    |
| 見出し未設定の同一代表の参照項目が多数      | 代表の名前／本文だけの一致で候補を参照数だけ増やさない      |
| 見出しと本文の複数一致                      | 同一IDの結果は一つ。代表と参照項目の結果は区別              |
| Markdownの見出し・強調・リンク・inline code | 表示した名前で検索／補完でき、本文とリンク先は書換わらない  |
| 全角／半角・大文字／小文字・同じ名前        | 正規化一致と曖昧候補の明示。保存値とIDを維持                |
| 名前変更・別名削除・移動・切り出し          | 索引とパンくずを更新し、既存リンクUUIDは維持                |
| 削除→復元→完全削除                          | 通常候補から除外／同ID復元／除去済み本文や名前のcache非露出 |
| 候補取得中に入力／選択変更、保存失敗        | 旧応答を破棄し、draft・設定値・保存済み結果を混同しない     |

最初は既存検索/補完Controller・navigation・validation・テスト資産を適合し、新しい検索サービスを重ねない。
初回の索引方式・ページング・候補件数上限は対象規模で測定し、結果の途中切捨てを全件一致の成功扱いにしない。
変更コストが低いのは正規化・順位・表示。原文から索引を再構築できるよう、parser/検索規則の版変更を扱う。
別名の所有や参照項目の到達IDを変える場合は保存データの意味に関わり、明示migrationと互換性fixtureが必要。
